# R2 — Windows Production Runtime

**Scope:** R2 only. Makes the backend startable as a real Windows
production process: a production launcher, a WinSW service definition,
a rotating operational log, per-install secret provisioning, and the
tests that pin all of it. Builds on R1 (`docs/R1_DATA_PATHS.md`), which
owns the path architecture (`DATA_DIR`, absolute `.env`, no CWD
dependence).

R2 does **not** install the service, does not install PostgreSQL, does
not run Alembic, does not change licensing/Backup Manifest contracts and
does not touch Flutter.

---

## 1. What a production start looks like

```bat
set DATA_DIR=C:\ProgramData\SupermarketPro
"C:\Program Files\Supermarket Pro\backend\.venv\Scripts\python.exe" ^
    "C:\Program Files\Supermarket Pro\backend\run_production.py"
```

Anything else — any CWD, no activated venv, no `--reload` — behaves the
same, because the launcher re-anchors itself:

1. **`DATA_DIR` is mandatory** (exit `2` if unset). A *relative* value
   anchors to the backend root, never to the CWD (same rule as R1).
2. **`<DATA_DIR>/config/.env` must exist** (exit `4` if missing) — the
   installer-written configuration. A `.env` in the CWD is ignored.
3. `_prepare_environment()` sets `DATA_DIR`, forces `APP_ENV=production`,
   sets `PYTHONDONTWRITEBYTECODE=1` (never write `__pycache__` into a
   read-only Program Files tree) and `chdir`s to the backend root.
4. **Secrets are provisioned first**, before `app.core.config` is
   imported — otherwise `Settings()` would evaluate the placeholder
   validator before unique per-install values existed (§3).
5. The secrets are re-checked against the placeholder set; anything
   repository-shaped fails closed (exit `4`).
6. Ctrl+C / Ctrl+Break handlers are installed (§4).
7. `uvicorn.run(app="app.main:app", reload=False, workers=1,
   log_config=None, access_log=True, host=<cfg>, port=<cfg>)`.

`--check` performs steps 1–5, prints the resolved runtime as JSON and
exits `0` without serving. It never prints a secret value.

### Exit codes

| Code | Meaning |
|---|---|
| `0` | clean start/stop, or successful `--check` |
| `1` | the server failed after configuration was accepted (bind error, import error) |
| `2` | usage error / `DATA_DIR` missing |
| `3` | secret provisioning refused (corrupted file, missing when load-only) |
| `4` | configuration invalid (missing `.env`, unusable settings, placeholder secret) |

Development is untouched: `python -m uvicorn app.main:app --reload` from
`new_app/backend` still works exactly as before.

## 3. Per-install secrets

`APP_SECRET_KEY` / `JWT_SECRET_KEY` shipped in the repository would let
anyone who reads the repo forge sessions for *every* installation.
R2 provisions them on first start:

```
C:\ProgramData\SupermarketPro\config\
    .env           installer-written (DATABASE_URL, settings)
    secrets.env    generated by the backend on first start
```

`secrets.env` holds two `KEY=VALUE` lines with `secrets.token_urlsafe(48)`
values (384 bits of CSPRNG output, 64 URL-safe characters).

Guarantees:

* **Generated once.** The file is created with `O_CREAT | O_EXCL` and is
  *never* rewritten — restarts and upgrades cannot rotate a customer's
  secrets (which would invalidate every active session).
* **Fail closed.** A file that exists but is unreadable, truncated,
  binary, missing a key, malformed, too short or holding a placeholder
  raises `SecretsError` (launcher exit `3`) and is left byte-for-byte
  untouched. Nothing is "repaired".
* **Installer secrets win.** If `.env` already carries real values for
  both keys, nothing is generated and no `secrets.env` is created.
* **Process environment wins.** Valid values are published with
  `os.environ.setdefault`, so an explicitly exported variable still
  outranks them.
* **Never logged.** Error messages name the *key* and the *path*, never a
  value; the logging redaction layers (§5) scrub the actual values out of
  every rendered line as a second line of defence.
* **Import order.** `app/core/secrets.py` imports nothing from
  `app/core/config.py` — the launcher must provision before `Settings()`
  exists. This is asserted by a test.

`app.core.config` now rejects **every** known placeholder — the two
repository defaults *and* the two `.env.example` copy-paste strings —
when `APP_ENV=production` (development still only warns).

## 4. Graceful shutdown and the service definition

`winsw/SupermarketProBackend.xml` (WinSW v2/v3, **not installed by R2**):

| Setting | Value | Why |
|---|---|---|
| `<executable>` / `<arguments>` / `<workingdirectory>` | absolute paths into `C:\Program Files\Supermarket Pro\backend` | the SCM may start the service from any CWD |
| `<env>` | `DATA_DIR`, `APP_ENV=production`, `PYTHONDONTWRITEBYTECODE=1` | R1 path architecture + explicit intent |
| `<startmode>` / `<delayedAutoStart>` | `Automatic` / `true` | start after boot, give the machine (and PostgreSQL, once installed) time |
| `<stoptimeout>` | `30 sec` | WinSW sends Ctrl+C, then waits for the process to exit by itself |
| `<onfailure>` ×3 + `<resetfailure>` | `restart` after 10 s, 30 s, then always; counter resets after 1 h | controlled recovery, not a tight crash loop |
| `<logpath>` + `<log mode="roll-by-size">` | `C:\ProgramData\SupermarketPro\logs`, 20480 KB × 10 | raw stdout/stderr (crash traces, anything emitted before app logging exists) |
| `<serviceaccount>` | `NT AUTHORITY\NetworkService` | low privilege, **no password stored in the XML** |
| `<depend>` | commented out | R2 does not install PostgreSQL; the installer adds it later |

### Why exit code 0 on stop matters

uvicorn captures `SIGINT`/`SIGBREAK`, restores the *previous* handlers on
the way out, then re-raises the captured signal. On Windows the previous
handler for `SIGBREAK` is the default one, which terminates the process
with a **non-zero** status even after a perfectly graceful shutdown —
WinSW would then report a failure and `<onfailure>` would restart the
service on every manual stop.

`install_signal_handlers()` therefore installs `KeyboardInterrupt`-raising
handlers for `SIGINT` and `SIGBREAK` *before* uvicorn starts; when uvicorn
restores and re-raises, the launcher logs `production_stopped` and returns
exit `0`. A `KeyboardInterrupt` during the preparation phase (before
uvicorn installs anything) is caught at the `__main__` level for the same
reason.

Verified end-to-end: a real server process started from an unrelated CWD
answers `/api/v1/health/live` with 200, receives `CTRL_BREAK_EVENT`, logs
its lifespan shutdown to `<DATA_DIR>\logs\backend.log` and exits **0**.

## 5. Operational logging

`app/core/logging.py` adds a rotating file sink on top of the existing
stdout/structlog behaviour:

* **Enabled automatically when `DATA_DIR` is set** (production); disabled
  in development, so nothing new is written to `<backend>/logs`. Override
  with `LOG_FILE_ENABLED` (`1/0`, `true/false`, `yes/no`, `on/off`;
  empty = auto).
* **Location:** `<LOG_DIR>/<LOG_FILE_NAME>` → by default
  `C:\ProgramData\SupermarketPro\logs\backend.log`. `LOG_FILE_NAME` must
  be a bare file name (no path separators) — validated.
* **Format:** `%(asctime)s %(levelname)s %(name)s %(message)s` on every
  line, so foreign records (uvicorn, SQLAlchemy, tracebacks) are equally
  searchable next to the structured JSON the application emits.
* **Rotation:** size based — `LOG_MAX_BYTES` (default 5 MiB, minimum
  1024) then `LOG_BACKUP_COUNT` files retained (`backend.log.1 … .N`,
  default 10). Total retained volume ≈ `LOG_MAX_BYTES ×
  (LOG_BACKUP_COUNT + 1)`.
* **Failure never blocks startup:** an unusable log directory (path is a
  file, no permission, full disk) drops the sink with a stderr warning
  and stdout logging continues.

Two redaction layers, both active on the file *and* stdout:

1. **Key masker** (structlog processor): values of sensitive *keys*
   (`password`, `secret`, `token`, `api_key`, `authorization`,
   `activation_code`, `private_key`, `machine_id`, `fingerprint`,
   `credential`) become `***` before the event is rendered.
2. **Value scrubber** (renderer wrapper + a handler-level
   `_RedactingFilter`): the *actual* configured secret values
   (`APP_SECRET_KEY`, `JWT_SECRET_KEY`, the `DATABASE_URL` password) are
   removed from every rendered line. The handler filter additionally
   covers records that never pass through structlog (third-party
   libraries).

`setup_logging()` stays idempotent: repeated calls (one per lifespan
start) rebuild the renderer and *replace* the file handler instead of
stacking it.

## 6. Least-privilege ACLs (`winsw/grant_data_dir_acl.ps1`)

Shipped, **not executed by R2** (installer/operator step, documented in
`winsw/README.md`):

1. **Data root** `C:\ProgramData\SupermarketPro`: create if missing, strip
   inherited ACEs (`/inheritance:r /T /C`) so ordinary local users cannot
   read `config\secrets.env`, then grant SYSTEM + Administrators `F` and
   the service account `M`.
2. **Installation tree** `C:\Program Files\Supermarket Pro`: grant the
   service account `RX` only — **never** `M`/`F`. The backend must run
   without write access to Program Files (R1 §4).

The script **refuses to run** when the data root would be inside Program
Files.

## 7. Development vs production (summary)

| | Development (`DATA_DIR` empty) | Production (`DATA_DIR` set) |
|---|---|---|
| Entry point | `python -m uvicorn app.main:app --reload` | `run_production.py` (or the WinSW service) |
| `.env` | `<backend>/.env` | `<DATA_DIR>/config/.env` (process env `DATA_DIR`) |
| Secrets | repository placeholders (warned) | `<DATA_DIR>/config/secrets.env`, generated once, placeholders **rejected** |
| `APP_ENV` | `development` | forced `production` |
| Workers / reload | `--reload`, dev server | `workers=1`, `reload=False` (hard invariants: rate limits and pairing state are process-local) |
| Logs | stdout only | stdout **+** `<DATA_DIR>/logs/backend.log` (rotating) |
| Stop | Ctrl+C | WinSW Ctrl+C → exit `0` |
